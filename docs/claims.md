# Claims and their limits

Every security claim the guides make, with the condition it needs, what it does not cover, and the host test that
checks it against the chip model. The CTest `se05x_docs_claims` fails when a test named here no longer exists, so a
claim cannot quietly outgrow the code. None of these is verified on hardware yet; the bench steps are on each guide
and on [Ambiguities](ambiguities.md).

| Id | Claim | Holds when | Does not cover | Test |
| --- | --- | --- | --- | --- |
| C1 | Facade calls on keys, counters and signature verification are refused unless answers are authenticated (R-MAC), with nothing sent | always | `Attest`, which needs no R-MAC because it checks the chip's own signature, and a C-MAC-only channel, which authenticates commands but not answers | `Integrity: platform SCP03 at C-MAC only answers nothing the facade trusts` |
| C2 | `Store`/`Load` with `Protection::Secret`, and `Agree`, are refused unless traffic is encrypted both ways | the caller passes `Protection::Secret` for a secret object | `Load(..., Protection::Public)` of a secret object over a channel without R-ENC (for example `CMacCDecrypt`) reads it unencrypted: always pass the protection the object was stored with | `Integrity: C-MAC and R-MAC admits keys and counters, not secrets` |
| C3 | A counter floor cannot be lowered or deleted and re-created lower | the counter was made by `CreateCounter` | a factory reset, which removes it | `Integrity: the floor cannot be lowered by delete and re-create` |
| C4 | `Find` and `CreateCounter` adopt only a persistent object of the right class and origin with the facade's exact policy | the chip returns the policy as written (A34) | a `Sign` and a `TlsClient` key, whose policies are the same | `Integrity: the adoption check compares class, origin, policy and lifetime each on its own` |
| C5 | A store cut short is never read back as a value | the chip does not leave 0xA5 in an unwritten byte (A35) | the object stays until erased | `Integrity: a store cut short before its completion marker is never read back as data` |
| C6 | A replayed or older attested answer is refused | the trusted attestation key is genuine | a server: the check runs on the host only | `Facade: a replayed attested answer is refused (host nonce, strict timestamp order)` |
| C7 | An ECDH peer that is not on P-256 is refused before sending | always | the peer's identity: authenticate the peer key yourself | `Guards: a peer or trust anchor that is not on P-256 is refused before sending` |
| C8 | A facade call is admitted only when its worst-case APDU count fits under the ceiling, so an answered call never passes it, and the count spans reopens and session handshakes | one `Device` object per chip | the recovery after a 0x66A6 answer, which sends up to four APDUs past the admitted cost (select, lifecycle read, platform SCP03 handshake), counted in `Used()` and tested as that bound, and APDUs sent by `se05x::Device` calls you make directly, which are counted but not admitted | `Guards: every facade path stays within its admitted cost at the budget's edge`, `Guards: a 0x66A6 answer at the edge passes the ceiling by at most the four recovery APDUs` |
| C9 | One WTX grants at most 30 s and the WTX of one command at most 180 s | always | the time before the first WTX (the command class deadline) | `One WTX grants at most 30 s, and the WTX of one command at most 180 s in all` |
| C10 | The bare 9000 of a session-ending command is accepted once, for that command only | the command is `DeleteAll` in an applet session | that answer is not authenticated (A22) | `A bare 9000 is accepted once after ExpectSessionEnd, never on a later answer` |
| C11 | Facade policies name the default session and the applet session they were made in | id 0 is the default session only (A20) | other sessions: the chip refuses them | `Integrity: a facade policy names the AESKey session it is created in (A20)` |
| C12 | Once platform SCP03 was open, the device sends no applet command in the clear | until `Recover()` or `Open()`, which redo the handshake | plain commands a probe sends itself before `RequirePlatformScp` (see [Security model](security-model.md)) | `Sessions: the applet stage never sends in the clear once platform SCP03 is required` |
| C13 | The facade refuses applet 3.x and 6.x before sending anything | always, after the argument checks | the device layer, which works on 3.x and 6.x | `Facade: applet 3.x and 6.x are refused before anything is sent` |
| C14 | A facade counter cannot be lowered, deleted or re-created lower | the counter was made by `CreateCounter` | raising it: a host holding the platform SCP03 keys or the session credential can raise it to 0xFFFFFFFF, which blocks every later update (a denial of service, see [Anti-rollback](tasks/anti-rollback.md)) | `Integrity: the floor cannot be lowered by delete and re-create` |
