Detailed Description

A minimal, strict X.509 v3 certificate parser (an RFC 5280 subset) for the PKI layer.

Copyright
Copyright (c) 2026 The driver-se05x authors. SPDX-License-Identifier: MIT

ParseCertificate() reads one DER certificate into a Certificate of views into the caller's bytes (nothing is copied, nothing allocates). It accepts what a device certificate chain needs and refuses the rest with a Reason, never by ignoring it:

Accepted Refused
version 3 (RFC 5280 4.1.2.1) v1 and v2 (UnsupportedVersion)
serial: positive, at most 20 octets (4.1.2.2) zero, negative, longer (BadInteger)
ecdsa-with-SHA256 / -SHA384 without parameters (RFC 5758 3.2), Ed25519 (RFC 8410 3) any other

algorithm (UnsupportedAlgorithm); the inner and outer algorithm differing (AlgorithmMismatch, 4.1.1.2) | | keys: P-256, P-384 uncompressed (RFC 5480 2), Ed25519 (RFC 8410 4) | other curves (UnsupportedCurve), compressed points (BadPublicKey) | | names of UTF8String, PrintableString, IA5String values | other string types (BadString); an empty issuer (BadName, 4.1.2.4); an empty subject without a critical subjectAltName (BadName, 4.1.2.6) | | UTCTime through 2049, GeneralizedTime from 2050, both Z to the second (4.1.2.5) | any other form (BadTime) | | basicConstraints, keyUsage, subjectAltName, extKeyUsage, subjectKeyIdentifier, authorityKeyIdentifier; other extensions when not critical (4.2) | an unknown critical extension (UnknownCriticalExtension); a duplicate (DuplicateExtension); unique ids (UniqueIdPresent) |

The parser checks the encoding and the profile; it does not check a signature, a time or a chain: that is VerifyChain() (se05x_pki_verify.hpp). Names are compared byte for byte there (a stricter rule than RFC 5280 7.1, which a chain from one issuer meets).
