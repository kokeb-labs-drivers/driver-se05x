# Third-party data in tests/vectors

Two files here derive from the vendor middleware.

`nxp_layouts.hpp` holds facts read from the source text of the vendor middleware, used here as a
test oracle:

- the four header bytes of 49 command builders (where they are constants);
- the TLV tag numbers each of 60 builders can write, in order.

It holds no middleware code, keys or other data. It is generated by
`tools/oracle/extract_layouts.py`, which reads the checkout as text and compiles or runs nothing.

`nxp_oracle_vectors.hpp` holds the commands the middleware's command builders produced for applet
7.2 (`oracle::v7`) and 3.x (`oracle::v3`): header bytes, TLV body and the builder's has-Le flag.
The inputs are the synthetic values of `tools/oracle/oracle_capture.c` (counting patterns, fixed
identifiers); no key material. The owner generated it with `tools/oracle/build_oracle.sh`, which
compiles two files of the same checkout in a temporary directory outside the repository.

- Source: NXP Plug & Trust middleware (`plug-and-trust`), commit
  `7102413e0457d3dfa4fc4be686ca8ec50bd9f5e2`.
- Files read: `hostlib/hostLib/se05x_03_xx_xx/se05x_APDU_impl.h`, `se05x_04_xx_APDU_impl.h`,
  and the constants in `hostlib/hostLib/inc/se05x_enums.h`, `se05x_const.h` and `se05x_tlv.h`.
- Licence of the source: BSD 3-Clause, reproduced below.

`attest_vectors.hpp` is not third-party data: `tools/oracle/attest_vectors.py` makes it from
the application notes with a key made for the run.

`pki_vectors.hpp` is not third-party data either: OpenSSL made its certificates from keys generated
for that run and then deleted. Its two certification requests use the published test keys of
RFC 6979 (A.2.5) and RFC 8032 (7.1, TEST 1), so the tests can rebuild them.
