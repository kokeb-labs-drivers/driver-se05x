Getting started by job¶

One short path for each thing people use a secure element for. Each path names the calls, the chip objects and policies they create, what can go wrong and where the chip documents it. Open the device first (Quickstart); every path below starts from an open se05x::Device and, for the facade, an se05x::hrot::Device bound to it.

Secure messaging first

Every facade key forbids use without secure messaging, and so do counters and secret data: over a bus that can be probed, an unauthenticated answer (a signature check, a counter value) could be forged, and a clear one read. Open the device with platform SCP03 (or an AESKey session) before these jobs. A call whose result you act on (keys, counters, verification) needs authenticated answers, an R-MAC layer (CMacRMac or Full); ECDH and Protection::Secret data need encryption both ways as well (Full). Otherwise the facade refuses with PolicyDenied (layer Hrot) and sends nothing. Identity, random numbers, public data and certificates work without it. For a root of trust set ScpPolicy::Require: Auto decides from an unauthenticated answer (Security model).

Open a secure channel¶

Channel Call When
Platform SCP03 Device::SetPlatformKeys(), then Open() with Config::scp_policy The bus can be probed; mandatory on SE050F and when the chip requires it
AESKey session BeginAesKeySession() SCP03 at the applet, one AES authentication object
ECKey session BeginEcKeySession() Bind one host key pair to the chip
UserID session BeginUserIdSession() Application separation under a trusted host OS; no secure messaging

Platform SCP03, with the keys as handles of your crypto port (never key bytes in the image, never a vendor default key set in a product):

/// Open the chip with platform SCP03. The keys are handles in your crypto port: never compile key
/// bytes into the image, and never use a vendor default key set in a product.
template <PortSet P>
Error OpenSecure(se05x::Device<P>& device, KeyRef platform_enc, KeyRef platform_mac) noexcept {
  scp03::ChannelParams keys{};
  keys.keys.enc = platform_enc;
  keys.keys.mac = platform_mac;
  if (const auto given = device.SetPlatformKeys(keys); !given.ok()) {
    return given.error;
  }
  return device.Open().error; // Config::scp_policy = ScpPolicy::Require when the device was built
}

An AESKey session over the default session:

/// Open an AESKey session with an authentication object of the chip. `key` is a handle in your
/// crypto port; the session ends with EndSession() or Close().
template <PortSet P>
Error OpenAesKeySession(se05x::Device<P>& device, ObjectId credential, KeyRef key) noexcept {
  AesKeySessionParams params{};
  params.credential = credential;
  params.keys.enc = key;
  const auto opened = device.BeginAesKeySession(params);
  if (opened.error == Error::NeedsReselect) {
    return device.Recover().error; // a lost frame under a session: recover, then open it again
  }
  return opened.error;
}

EndSession() closes it. A failed step wipes the session keys; a session that failed after CreateSession cannot be closed, so the device selects the applet again (AN12543 3.6.5 p. 35). The ECKey session is off unless the build sets SE05X_ENABLE_ECKEY_SESSION=1, and it needs the chip's ECKA key verified first (Device::ReadEckaPublicKey). A lost frame or a failed check under a session leaves the device NeedsReopen: call Device::Recover(), then open the session again. A UserID session alone is not secure messaging: the facade refuses key use over it. A facade policy names the default session (authentication object 0) and, when the facade runs inside an AESKey or ECKey session, that session's credential: id 0 does not cover other sessions (AN12543 3.7.1.2, p. 36), so an object made in one session is refused in another (Ambiguities, A20). Diagrams and details: Secure channels.

Provision a device key¶

CheckPlan() sends nothing and says whether each slot's policy builds for this chip. Provision<U>(slot) generates a NIST P-256 key pair inside the chip (WriteECKey with no key bytes, AN12543 p. 80) under the strict policy of its use: the use's rule, read of the public half, secure messaging; write, delete and regenerate forbidden. A slot already in use gives ObjectExists and nothing is changed; Find<U>(slot) returns the key.

/// Generate the device key in slot 0 and read its public half.
template <PortSet P>
Error ProvisionDeviceKey(hrot::Device<P>& hrot, hrot::EcPublicKey& public_key) noexcept {
  constexpr hrot::Slot kDeviceKey = hrot::Slot::At<0>();
  const std::array<hrot::SlotPlan, 1> plan{hrot::SlotPlan{kDeviceKey, hrot::KeyUse::Sign}};
  if (const auto checked = hrot.CheckPlan(plan); !checked.ok()) {
    return checked.error; // nothing was sent
  }
  const auto key = hrot.template Provision<hrot::KeyUse::Sign>(kDeviceKey);
  if (!key.ok()) {
    return key.error; // ObjectExists: the slot was provisioned before; use Find()
  }
  const auto pub = hrot.GetPublicKey(key.value);
  public_key = pub.value;
  return pub.error;
}

A facade key is permanent

The strict policy forbids deleting the key, so the slot stays occupied for the life of the chip; only a factory reset (Irreversible operations, DeleteAllObjects) removes it. Plan the slots before you provision.

The key never leaves the chip. A Key<U> (SignKey, AttestKey, AgreeKey, TlsKey, VerifyKey) names the slot only, only the facade makes a valid one, and each call takes only its own key type: Sign() with an AgreeKey does not compile.

Attest a key or a value¶

Attest(key, slot) returns Verified<AttestedValue> only when every check passed:

  • a fresh 16-byte nonce from the host's crypto port for every request, never from the chip being attested (its answer could be replayed with an old attested answer);
  • applet 3.x (format 1): the chip echoes the nonce and it must match;
  • applet 7.x (format 2): the signature covers the hash of the command the chip received and the returned TLVs (AN12543 p. 19);
  • a timestamp later than the last one accepted from this chip, across reopens (AN12543 3.9, p. 42), the signature with the attestation key you trust over the TLVs exactly as the chip returned them, and the 18-byte unique id equal to the one read in this open of the device (else Counterfeit).
/// Prove that the key in slot 0 lives in this chip. `vendor_public` must come from a verified
/// certificate (the se05x::pki layer) or your factory record, never from the same chip.
template <PortSet P>
Error AttestDeviceKey(hrot::Device<P>& hrot, const hrot::EcPublicKey& vendor_public,
                      hrot::EcPublicKey& attested_key) noexcept {
  const auto trusted =
      hrot::TrustAttestationKey(FromReserved(ReservedId::RootOfTrustKey), vendor_public);
  if (!trusted.ok()) {
    return trusted.error;
  }
  const auto value = hrot.Attest(trusted.value, hrot::Slot::At<0>());
  if (!value.ok()) {
    return value.error; // AttestationInvalid, Counterfeit: do not trust this chip
  }
  const hrot::AttestedValue& checked = value.value.Get(); // a Verified<T> exists only if checked
  if (checked.data.length != attested_key.point.size()) {
    return Error::FrameError; // not an uncompressed P-256 point
  }
  for (std::size_t i = 0U; i < attested_key.point.size(); ++i) {
    attested_key.point[i] = checked.data.bytes[i];
  }
  return Error::Ok;
}

The trusted public key decides what the attestation proves. For the vendor key (0xF0000012, AN12436 p. 10) take it from the vendor certificate after its chain was verified (the optional se05x::pki layer); reading it from the same chip proves nothing. A value that failed any check cannot become a Verified<T>: you get AttestationInvalid. The facade returns up to 256 bytes of attested data.

Sign and verify¶

Sign(key, digest) signs a SHA-256 digest you computed (ECDSA takes a digest, AN12543 p. 101) and returns the DER signature. VerifySignature() fails closed: Ok only for a valid signature, AttestationInvalid for one that does not verify, never a true/false to forget.

/// Sign a SHA-256 digest with the device key and check the signature on the chip.
template <PortSet P>
Error SignAndVerify(hrot::Device<P>& hrot, hrot::Digest digest, hrot::Signature& out) noexcept {
  const auto key = hrot.template Find<hrot::KeyUse::Sign>(hrot::Slot::At<0>());
  if (!key.ok()) {
    return key.error;
  }
  const auto signature = hrot.Sign(key.value, digest);
  if (!signature.ok()) {
    return signature.error; // PolicyDenied: no secure messaging
  }
  out = signature.value;
  return hrot.VerifySignature(key.value, digest, out.View()).error; // Ok only when valid
}

Agree a key (ECDH)¶

Agree(key, peer, shared) returns the 32-byte x coordinate of the shared point (ECDHGenerateSharedSecret, AN12543 p. 105) into a SecretBuffer that wipes itself. The secret crosses the bus encrypted only (Full). A chip whose extended features forbid ECDH (EXTCFG_CRYPTO_EC_FORBID_ECDH) gives Unsupported before anything is sent.

/// Agree a secret with a peer. The key lives in slot 1; the secret is wiped when `shared` goes.
template <PortSet P>
Error AgreeWithPeer(hrot::Device<P>& hrot, const hrot::EcPublicKey& peer,
                    SecretBuffer<32>& shared) noexcept {
  auto key = hrot.template Find<hrot::KeyUse::Agree>(hrot::Slot::At<1>());
  if (key.error == Error::ObjectNotFound) {
    key = hrot.template Provision<hrot::KeyUse::Agree>(hrot::Slot::At<1>());
  }
  if (!key.ok()) {
    return key.error;
  }
  return hrot.Agree(key.value, peer, shared).error;
}

Import a key¶

Generating keys inside the chip is the default. A trust anchor (a firmware-signing root, a server key) comes from outside: ImportPublicKey() stores it in a key slot where it can verify and never be changed or deleted.

/// Keep the firmware-signing root in the chip: it verifies, and nobody can replace it.
template <PortSet P>
Error StoreFirmwareRoot(hrot::Device<P>& hrot, const hrot::EcPublicKey& root) noexcept {
  return hrot.ImportPublicKey(hrot::Slot::At<2>(), root).error;
}

/// Verify a firmware image's signature with that root.
template <PortSet P>
Error CheckFirmware(hrot::Device<P>& hrot, hrot::Digest image_digest, ByteSpan signature) noexcept {
  const auto root = hrot.template Find<hrot::KeyUse::Verify>(hrot::Slot::At<2>());
  if (!root.ok()) {
    return root.error;
  }
  return hrot.VerifySignature(root.value, image_digest, signature).error;
}

A symmetric key travels wrapped (RFC 3394) under a key-encryption key already in the chip, so the plain key never exists on the host (WriteSymmKey, AN12543 p. 83). The facade has no symmetric keys; this is the device layer:

/// Import an AES key wrapped (RFC 3394) under a key-encryption key already in the chip: the plain
/// key never exists on the host. This is the device layer: the facade has no symmetric keys.
template <PortSet P>
Error ImportWrappedAesKey(se05x::Device<P>& device, ObjectId kek, ObjectId target,
                          ByteSpan wrapped) noexcept {
  const auto policy = PolicyBuilder<AppletGeneration::V7, ObjectClass::AesKey, Profile::Strict>{}
                          .ForAllOthers()
                          .template Allow<Rule::Encrypt>()
                          .template Allow<Rule::Decrypt>()
                          .RequireSecureMessaging()
                          .template Forbid<Rule::Write>()
                          .template Forbid<Rule::Delete>()
                          .Build();
  if (!policy.ok()) {
    return policy.error;
  }
  WriteSymmKeyArgs args{};
  args.id = target;
  args.policy = &policy.value;
  args.type = SymmKeyType::Aes;
  args.key = wrapped; // 24 or 40 bytes: an AES-128 or AES-256 key wrapped
  args.kek = kek;
  return device.template Execute<Command::WriteSymmKey>(args).error;
}

A plain private key can be imported with WriteEcKeyArgs for provisioning only; it shows Origin::External in every attestation. ImportExternalObject (AN12543 p. 88) is held: the vendor asks to be contacted before use.

Store data¶

Store(slot, data, protection) creates a binary object of 1 to 2048 bytes (written 256 bytes per command); Protection::Secret needs secure messaging for every read, write and delete (AN12543 p. 84), over encrypted traffic. Load() reads the size from the chip, then the data. A slot in use gives ObjectExists: Erase() first. The object is one byte longer than the data: Store writes a completion marker after the last chunk and Load refuses an object without it (FrameError), so a store cut short by a power loss is never read back as a value; a store that fails while powered deletes the object (A35), except after SW 0x66A6 (ThroughputLimited), when the chip refuses work: then the object stays until Erase().

/// Keep a configuration blob that only a host with secure messaging reads back.
template <PortSet P>
Error SealConfig(hrot::Device<P>& hrot, ByteSpan config) noexcept {
  return hrot.Store(hrot::DataSlot::At<0>(), config, hrot::Protection::Secret).error;
}

/// Read it back; the length comes from the chip.
template <PortSet P>
Result<std::size_t> UnsealConfig(hrot::Device<P>& hrot, MutableByteSpan out) noexcept {
  return hrot.Load(hrot::DataSlot::At<0>(), out, hrot::Protection::Secret);
}

Read and store certificates¶

A certificate slot holds the bytes as given: the facade parses nothing. The vendor provisions certificates of its own keys (AN12436 Tables 8 and 9, p. 10). Anyone on the bus may read a certificate, and also replace it: its integrity is its signature, so check it before you trust it. Building a CSR and parsing or verifying X.509 is the optional se05x::pki layer.

/// Store the device certificate your CA issued, and read it back for the TLS stack. The bytes are
/// not parsed here: building and checking X.509 is the se05x::pki layer.
template <PortSet P>
Error KeepCertificate(hrot::Device<P>& hrot, ByteSpan der, MutableByteSpan out) noexcept {
  constexpr hrot::CertSlot kDeviceCert = hrot::CertSlot::At<0>();
  if (const auto stored = hrot.StoreCertificate(kDeviceCert, der); !stored.ok()) {
    return stored.error; // ObjectExists: EraseCertificate() first to replace it
  }
  return hrot.LoadCertificate(kDeviceCert, out).error;
}

Monotonic counters¶

A counter slot holds a 4-byte counter that only goes up (WriteCounter, AN12543 p. 84), created with its start value in one command. Its policy forbids delete, so a floor cannot be deleted and created again lower; only a factory reset removes it. CheckFloor(slot, version) fails closed: Ok only when version is not below the counter, PolicyDenied for an older one. RaiseCounterTo() moves the floor in one command, never down; a loop of CounterIncrement() would spend the APDU budget (S-17). See the HRoT cookbook.

/// The anti-rollback check at boot: refuse an image older than one that ran before.
template <PortSet P>
Error BootCheck(hrot::Device<P>& hrot, uint32_t image_version) noexcept {
  constexpr hrot::CounterSlot kFloor = hrot::CounterSlot::At<0>();
  return hrot.CheckFloor(kFloor, image_version).error; // Ok only when not below the floor
}

/// After the new image booted and passed its self test: raise the floor in one command.
template <PortSet P>
Error CommitImage(hrot::Device<P>& hrot, uint32_t image_version) noexcept {
  return hrot.RaiseCounterTo(hrot::CounterSlot::At<0>(), image_version).error;
}

Lifecycle and lock¶

Locking the transport, requiring platform SCP03, restricting object creation, changing applet features and the factory reset are lifecycle operations (Lifecycle). Those that cannot be undone exist only in a build with SE05X_ENABLE_IRREVERSIBLE=1 and go plan, confirm, apply (Irreversible operations):

/// Lock the transport for good. Run it from a session with the Transport credential; show the
/// plan's effect to a person; the phrase is typed by that person, not by the code that planned it.
template <se05x::PortSet P>
se05x::Error LockForGood(se05x::Device<P>& device, const se05x::irreversible::Phrase& typed,
                         void (*show)(const char* effect)) noexcept {
  using Op = se05x::irreversible::SetLockStatePersistent;
  se05x::irreversible::Operations<P> operations(device);
  const auto plan = operations.PlanSetLockStatePersistent(); // sends nothing
  if (!plan.ok()) {
    return plan.error; // ConditionsNotSatisfied: not a Transport session; WrongState: locked
  }
  show(plan.value.Effect());
  return operations.Apply(plan.value, se05x::irreversible::Confirmation<Op>{typed}).error;
}
