Detailed Description

The interface between the command layer and the APDU layer: Codec<Command>.

Copyright
Copyright (c) 2026 The driver-se05x authors. SPDX-License-Identifier: MIT

Frozen contract, with one amendment (the three-argument Decode). For each Command C the APDU layer specialises Codec<C> with:

  • Encode(args, out) writes the command APDU (header, TLVs, Lc and Le, no secure messaging) into out and returns its length, or InvalidArgument / Unsupported (an argument the specification refuses; every byte written is zeroed) / BufferTooSmall;
  • Decode(args, data, reply) parses the response body (the bytes before the status word) into reply and copies the output of the command into the caller buffers named in args (args.out, args.signature, ...). It never truncates: a buffer that is too short is BufferTooSmall. This is the form Device calls for every command;
  • Decode(data, reply), the original form, for the commands that write no caller buffer (kWritesCallerBuffers == false); for the others it returns InvalidArgument, because the reply holds only lengths and the output would be lost.

The status word is not the codec's: Device maps it with apdu::StatusToError() in the context of the command, then calls Decode only for 0x9000. The primary template below is the stub: every function returns NotImplemented. The APDU package writes each command's codec group by group in se05x_apdu_*.hpp as a struct in se05x::codecs and selects it with an overload codecs::CodecFor(codecs::CommandTag<C>); the constrained Codec<C> below then derives from it. All specialisations of Codec stay in this file (MISRA C++:2023 Rule 6.2.3). A command with no overload keeps the stub, which is how the integration check finds a command nobody wrote.
