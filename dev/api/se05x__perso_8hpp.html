Detailed Description

The PERSO applet of the SE051: read-only by default, writes and module deletion behind irreversible tokens.

Copyright
Copyright (c) 2026 The driver-se05x authors. SPDX-License-Identifier: MIT

Written from AN13015 Rev 1.4 Appendix B (pp. 45-51): the PERSO applet (AID A0000003965453000000010340000000) configures the chip's own bus behaviour: the I2C address (tag 0x800D), clock stretching, power saving and the T=1 flavour (0x800E), the ATR and CIP interface bytes (0x800F, 0x8015), history bytes and the deletion of optional OS modules (0x8017). It needs no authentication, so while it is selectable anyone on the bus can change those settings (AN13015 p. 19): Probe() reports that as a security finding, and Device::Open() copies it into Capabilities::perso_selectable.

The library is read-only on this applet. Write() and DeleteModule() exist only when kIrreversibleEnabled and take their own confirmation token (S-10), and even then they return Unsupported and send nothing: a wrong protocol or address leaves the chip unreachable from this host build (the flavour is chip-side and not recoverable from the host), a deleted module is gone for good, and no write path has been checked on a chip. iot_base is not in Module: it is never offered (AN13015 Table 2 lists it as deletable after iot_extended). Settings take effect after the next chip reset (AN13030 p. 261).

Selecting PERSO deselects the IoT applet: every applet session and transient object is gone, and the device selects the IoT applet again afterwards.

Read: 80 02 P1 P2 01 len 00 with the tag in P1 P2 and the expected length; the answer is TLV[TAG_1] (AN13015 Tables 10 to 12). SW 6700 means the expected length is shorter than the value; SW 6A81 means the chip does not have the item.
