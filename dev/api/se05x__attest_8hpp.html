Detailed Description

Attestation verification, one verifier type per format.

Frozen surface; the helpers are in se05x::attest::detail. The two formats are different types, so a format-1 rule cannot be applied to a format-2 answer (S-09):

  • AttestationFormat::V1 (applet 3.x, AN12413 3.2.7.2 and Table 106): the answer carries data, attributes, a 12-byte timestamp, the freshness echo, the 18-byte unique id and a signature over the concatenated values (data, attributes, timestamp, freshness, unique id; the I2C controller answer has no attributes); the echo must equal the 16-byte nonce the host sent.
  • AttestationFormat::V2 (applet 7.x, AN12543 3.2.7.2, Figure 4 and Tables 128, 131, 313): there is no freshness echo. The signature covers H(command) || TLV(0x41, data) || TLV(0x42, chip id) || TLV(0x43, attributes) || TLV(0x44, size) || TLV(0x4F, timestamp), where the command is the plain C-APDU as sent without its Le, H the digest of the attestation algorithm, and each TLV as the applet returned it; an absent data or attribute TLV is left out. The nonce is bound by the hashed command. The chip does not return the command (the earlier reading that it does came from the middleware guide); AttestedRead::echoed_command, when a lower layer fills it, must equal the command sent, byte for byte.

The verifier re-encodes the TLVs of a format-2 answer with the three-byte length form 82 xx xx: the form the applet uses in attested answers, and the one the middleware's verification rebuilds (AN12543 4.1.3.2 allows it for any length). A chip that answers with another form fails the signature check; nothing is accepted that was not signed.

The port verifies ECDSA with P-256 keys only, so the algorithms are the ECDSA ones: the digest is the leftmost 32 bytes of the hash, or the hash padded on the left (FIPS 186-4 6.4). RSA, Ed25519 and EcPlain are Unsupported.

In both formats the 12-byte timestamp (4 bytes persistent, incremented at every session open; 8 bytes transient, strongly monotonic; AN12543 3.9) must not go backwards across attested reads from one chip within one boot. The byte order is taken as the most significant byte first (AN12543 3.9 names the "most significant 4 bytes" persistent; not stated otherwise). The nonce is a fresh 16 bytes of the host's crypto port per request (Device::ReadAttested), never the attested chip's own RNG.
