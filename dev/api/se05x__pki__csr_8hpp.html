Detailed Description

PKCS#10 certification requests (RFC 2986) signed by a key that never leaves the chip or the crypto port: subject name and subjectAltName builders, BuildCsr(), VerifyCsr().

The request is 

CertificationRequest ::= SEQUENCE {
  certificationRequestInfo SEQUENCE { version 0, subject Name, subjectPKInfo,
                                      [0] attributes (extensionRequest, RFC 2985 5.4.2) },
  signatureAlgorithm, signature BIT STRING }

The signer (CsrSigner) gets the SHA-256 or SHA-384 digest of the info for ECDSA, or the info itself for Ed25519, and returns the signature; the private key stays where it is (the chip: DeviceSigner in se05x_pki_device.hpp; the crypto port: PortSigner). The builder checks the signature it gets back parses before it writes it, and VerifyCsr() checks the whole request against its own public key, which catches a key id that does not belong to the public key given.

Names are written with UTF8String values (RFC 5280 4.1.2.6), except countryName and serialNumber, which X.520 makes PrintableString. Attribute values are bytes (UTF-8): the layer never converts characters; Name::AddHex() writes bytes (the chip's unique id) as upper-case hex.
