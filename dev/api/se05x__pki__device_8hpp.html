Detailed Description

The chip side of the PKI layer: a CSR signer over a key in the chip, reading a public key back, and storing certificates and trust anchors in binary objects with read-only policies.

Every call goes through Device<P>, so the capability gate, the role check, secure messaging and the recovery rules of the device apply unchanged; a device failure comes back with the device's own Error and Detail.

Storage rules (AN12543 4.7.1.4 WriteBinary, 3.7.1 policies):

  • A certificate is written by one WriteBinary command that creates the object with its policy and its whole content, because a read-only policy refuses every later write. So it must fit one command (MaxStoredCertificate(), about 980 bytes with the default policy); a larger one is refused with ObjectTooLarge before anything is sent.
  • The policy may not grant Write to anyone, nor Delete to everybody (authentication object 0): either would let the certificate be replaced (PolicyAllowsWrite, nothing sent). CertificatePolicy(admin) builds the default: everybody reads; the administrator may also delete, for rotation by delete-and-create. A certificate nobody may delete can never change: that is an irreversible operation, created only by irreversible::Operations::PlanCreateImmutableObject; Device refuses it everywhere else (IrreversibleNotConfirmed, nothing sent).
  • An existing object is never overwritten (ObjectExists); the object is read back and compared after the write (ReadBackMismatch).

Not verified on hardware: the chip model of the tests stores binary objects and P-256 keys only; the P-384 and Ed25519 paths are checked against the codecs, not a chip.
