Detailed Description

GlobalPlatform SCP03 as a secure ApduTransport (platform SCP03 and the applet AESKey session), the applet session framing, and the UserID session.

Sources: GlobalPlatform Card Specification Amendment D (SCP03) as AN12543 and AN12413 apply it (AN12543 3.5, 3.6.3.2, 4.5.3; AN12413 3.4.2), errata JOS.2 (SE050 errata sheet 3.13), and the NXP middleware read as an oracle for the counter behaviour the chip shows. No platform key of any chip is in this repository: keys arrive as KeyRef handles (S-16).

Channel wraps a lower transport (the link): Open() runs INITIALIZE UPDATE and EXTERNAL AUTHENTICATE, Transceive() wraps the command (C-MAC, C-DECRYPTION), sends it and unwraps the response (R-MAC, R-ENCRYPTION), Close() releases every session key. The rules:

  • Session keys come from the SCP03 KDF (NIST SP 800-108 counter mode with AES-CMAC): S-ENC from the static ENC key, S-MAC and S-RMAC from the static MAC key, context host challenge || card challenge. The card cryptogram is checked before anything is sent with the keys.
  • C-MAC chaining: every C-MAC is CMAC(S-MAC, MCV || header || Lc || data); the full 16-byte result becomes the next MCV. The first MCV, for EXTERNAL AUTHENTICATE, is 16 zero bytes.
  • The encryption counter starts at 1 after EXTERNAL AUTHENTICATE, only ever increases (S-16: never rewound) and the channel closes rather than wrap it. The command ICV is AES(S-ENC, counter); the response ICV is AES(S-ENC, 0x80 || counter bytes 1..15).
  • Errata JOS.2: in platform SCP03 the chip advances its counter only for a command with data, and answers a command without data under the counter of the previous command. With ChannelParams::jos2_counter_rule (default) the channel does the same; without it the counter advances for every command, as in an applet session.
  • The R-MAC is checked on every response with SW 9000, short ones included (the middleware defect fixed in v04.08.02), with ct::Equal (S-08). A response with another status word must be the two status bytes only: SCP03 adds no R-MAC to an error, so its status word is not authenticated (the caller must not act on it as if it were). Anything else is SecureChannelError.
  • Any failure after the handshake started, a failed check, or a lower-transport error closes the channel and releases its keys (S-07); a channel never survives a link reset (S-15).

The applet's sessions (AN12543 3.6) are framed by session::Framer: CreateSession, then every command inside ProcessSessionCmd with the 8-byte session id. An AESKey session is a Channel with ChannelKind::AesKeySession. session::UserIdSession opens a UserID session: it carries no secure messaging (S-14), counts failed attempts on the host, and is marked so that no secure channel can be stacked on it.
