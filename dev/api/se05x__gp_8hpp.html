Detailed Description

The GlobalPlatform card manager: card data, key information and the platform key set.

Copyright (c) 2026 The driver-se05x authors. SPDX-License-Identifier: MIT

The card manager (the issuer security domain, AID A000000151000000) is a separate applet from the IoT applet: SelectCardManager() replaces the selected applet, so the device layer selects the IoT applet again afterwards and drops its sessions. The GET DATA calls need SelectCardManager() first on this object (WrongState otherwise, nothing sent).

Sources: GlobalPlatform Card Specification GET DATA (tags 9F7F CPLC, 00E0 key information template with entries C0: key id, version, type, length); the card identification data is the proprietary tag 00FE with sub-tag DF28 as the NXP GetInfo log prints it (AN12436 p. 2, AN13904 p. 4; the command bytes 80 CA 00 FE 02 DF 28 are not in the obtained documents: derived).

Replacing the platform keys (PutKeys) is irreversible (S-10): it exists only when kIrreversibleEnabled is true and takes a Confirmation<ReplacePlatformKeys>. Even then it returns Unsupported and sends nothing: PUT KEY carries each new key encrypted under the DEK, and the crypto port has no hook that encrypts one key handle under another, so the new keys would have to pass through the library in the clear (S-16). A port hook for it is a contract amendment.
