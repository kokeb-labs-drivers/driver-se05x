Detailed Description

Operations<P>: the plan-and-apply surface of every irreversible operation.

Every member exists only when kIrreversibleEnabled is true (SE05X_ENABLE_IRREVERSIBLE=1, default off): without it the members are not callable and the build of a caller fails.

The flow is plan, confirm, apply:

  1. Plan...() sends nothing. It checks the device state, the capability gate, the session role the command needs (ConditionsNotSatisfied), the arguments, and that the chip is not already in the requested state (WrongState), and returns a Plan<Op> with the target, a one-line effect for the operator and the arguments.
  2. A person reads the plan; the code builds Confirmation<Op>{Op::kPhrase}.
  3. Apply(plan, confirmation) is the only call that sends. It refuses a plan that was not prepared, a plan prepared for another device, or a confirmation that does not match, with IrreversibleNotConfirmed and nothing sent, then runs Device::ExecuteIrreversible (which checks the state, gate and role again) or the creating command.

Operations the driver cannot perform in this version return Unsupported from their Plan...() call, so no plan for them is ever prepared: ReplacePlatformKeys (PUT KEY needs a key-wrapping crypto hook, docs/secure-channels.md), ChangeI2cAddress (no applet command, ambiguity A7), ApplyAppletUpdate (SEMS Lite is out of this version) and ReplaceEcKeyCredential (the update of an authentication object's key is not described in the sources read). The two PERSO operations stay on perso::Perso. The facade (hrot) does not use this header.
