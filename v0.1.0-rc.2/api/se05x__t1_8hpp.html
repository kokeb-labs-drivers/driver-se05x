Detailed Description

The T=1 link over I2C: one command in flight, bounded waits, the recovery ladder (package 1).

The public surface below is frozen (the compile-only test pins every signature); only private members and helpers are added.

Link carries one command APDU and returns one response APDU (ApduTransport), in either frame flavour: NXP (UM11225: NAD 0x5A and 0xA5, one LEN byte) or GP (GPC_SPE_172: NAD 0x21 and 0x12, two LEN bytes, CRC most significant byte first). Rules it enforces:

  • One command in flight: a response is read out completely before the next block is written (UM11225 section 2, p. 4; errata I2C.1), and Open() reads out whatever an earlier host left unread, answering up to kSessionOpenWtxAllowance waiting-time extensions of it first.
  • One block per I2C write, never an empty write (UM11225 section 3.1.1.1, p. 13; errata I2C.2). The GP "ready to receive" probe by an address-only write (GPC_SPE_172 section 3.2.4) is never used: the link polls with reads only.
  • Every wait has a deadline (S-05): the block waiting time from the ATR or CIP, the command class timeout of Config::timeouts, Config::wtx_limit extensions per command, and an iteration cap derived from the deadline and the poll interval, so a clock that does not advance cannot hang the link. After a waiting-time extension the link waits the multiplier times BWT and at least wire::kMinWtxHostTimeoutMs (AN13904 section 8.3, p. 27), never past the command deadline.
  • Errors are retried Config::frame_retries times (R-block or retransmission, UM11225 section 2.4.1, p. 11), then the recovery ladder climbs (S-06): resynchronisation, interface soft reset, reselect (the layer above), chip reset (the NXP S-block 0xC6; in the GP flavour, where 0xC6 means RELEASE, the reset port), power cycle (reset port only), then TransportDead. A rung that cannot run is skipped; a stuck bus goes straight to the power cycle.
  • A resync or reset invalidates every session above the link: Transceive() then returns Resynced or NeedsReselect and never a half-answer (S-07, S-15). On any failure the bytes the link wrote into the response buffer are zeroed, and the link's own frame buffers are wiped after every command (S-01).

Not implemented: the host's own S(IFS request) (the link keeps the chip's IFSC and, in the GP flavour, the default IFSD of 64 bytes), S(ABORT), and the proprietary GP cold-reset S-block of the middleware (no published document defines it).
