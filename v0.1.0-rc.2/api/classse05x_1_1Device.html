Sessions

Each Begin...Session() needs a Ready device without a session, refuses on the host when Config::auth_attempt_limit failed attempts in a row were counted (AuthLocked, S-14, nothing sent), and on a failure after CreateSession selects the applet again (S-07). Platform SCP03, when open, stays underneath.

◆ Open()

template<PortSet P>
Result< void > se05x::Device< P >::Open ( )
noexcept

Validate the configuration, open the link, read the card identification data (OEF id) from the card manager, select the applet, read the extended feature bits (applet 7.x), run the probes (Config::probe_capabilities), read the lifecycle state (applet 7.x: ReadState), derive the capabilities and open platform SCP03 when Config::scp_policy or the chip requires it.

Returns
Ok; InvalidArgument (bad Config, nothing sent); WrongState (already open, or platform SCP03 required and scp_policy is Off or no keys were given); Counterfeit (no IoT applet answers the select); DeviceIdMismatch (an applet version or OEF id of no known part); ThroughputLimited; or the error of the link, of a command or of platform SCP03. On failure the link is closed and the device stays Closed.

◆ Recover()

template<PortSet P>
Result< void > se05x::Device< P >::Recover ( )
noexcept

Bring a NeedsReopen (or Ready) device back: drop every session (sending nothing), select the applet again, and open platform SCP03 again when it was open. When the select fails on the transport, climb the link's ladder from the resynchronisation once and select again. Sessions are lost; the caller opens them again (S-15).

Returns
